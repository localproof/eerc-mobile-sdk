# @localproof/eerc-sdk

Pure-JS, React-Native-safe client for Avalanche's **Encrypted ERC (eERC)**.

The official SDKs (`@avalabs/ac-eerc-sdk`, `@avalabs/eerc-sdk`) cannot run in React
Native: they depend on `snarkjs` (needs WebAssembly; Hermes has none), `blake-hash`
(a native node-gyp addon), and peer-dep on `wagmi`/`react`. eERC's core claim is
client-side proving, and it had no mobile path. This is that path.

No `ethers`, no React, no chain config — protocol logic only.

## What's in it

| module | |
|---|---|
| `crypto` | ElGamal over BabyJubJub, Poseidon PCT encrypt/decrypt, pluggable RNG |
| `keys` | keypair from seed, from an EVM signature, or an imported scalar |
| `inputs` | circuit input builders for register / transfer / withdraw |
| `balance` | decrypts an on-chain balance and cross-checks it against the ciphertext |
| `proof` | arkworks and snarkjs proofs to Solidity calldata |
| `abi` | protocol ABIs (no deployment addresses — those are app config) |

## Install

```sh
npm i github:localproof/eerc-mobile-sdk
```

React Native: `import 'react-native-get-random-values'` once, before the SDK, or
call `setRandomSource()` yourself.

## Reading a balance

The plaintext balance is **not** recoverable from the ElGamal ciphertext alone (that
needs a discrete log). It is reconstructed from `balancePCT` plus every pending
`amountPCT`; the ciphertext is then used to *verify* that reconstruction, which is
what the `consistent` flag reports.

```ts
const { balance, consistent } = decryptBalance(keys.formatted, onChainBalance);
```

## Gotchas

1. **Wrap every scalar circuit input in a single-element array.** The Rust witness
   stack silently zeroes bare scalars — no error, it emits a well-formed proof that
   fails verification. The builders here already do this.
2. **G2 coordinate order.** Arkworks emits Fp2 as `(c0, c1)`; Solidity verifiers want
   each pair reversed. `nativeToCalldata()` handles it.
3. **Use `contracts/prod/*.sol` verifiers** from upstream — they match the committed
   `circom/build/*.zkey`. The `contracts/verifiers/*` set is regenerated by upstream's
   `postinstall` and will reject proofs from those zkeys.
4. Key derivation is ours to choose: the circuits consume the secret **scalar** and
   only assert `pubKey == Base8 * scalar`. `keysFromScalar()` imports a key made by
   another eERC client.

## Integration test

Deploys real eERC contracts, registers two users, deposits, reads the sender's
**actual stored ciphertext back off-chain**, proves a transfer against it, and checks
both balances decrypt.

```sh
npm run setup      # clone upstream circuits + forge build
anvil &
npm run e2e                      # snarkjs prover
PROVER=native PROVER_DIR=/path/to/eerc-wallet/prover npm run e2e
RPC_URL=https://api.avax-test.network/ext/bc/C/rpc DEPLOYER_PK=0x… npm run e2e
```
